# Supported coordinator continuation

Issue #352; scope q352-a61d9c27; full-spec; M; fixed denominator 250 changed lines.

## Problem and scope

A phase recommendation is not a root model switch. Extend the shared model policy with
three supported paths and link existing forge/campaign coordinator guidance. Consume #351's
quest-log continuity checklist without another state store or protocol. Approved exclusions
and owners are frozen in WORK:SCOPE on #352; no launchers, config edits, worker assignment,
review isolation, escalation policy, telemetry, backlog edits or authority changes.

## Design

At a settled phase boundary, choose capability for the coordinator's remaining decisions.
A mechanical wait does not make unresolved scope or merge judgments mechanical; reviewer
selection is separate. Continue the current session if adequate. An actual exposed native
root control may be used only under effective settings/authority, with continuity recorded
before and settings/ownership/head/artifacts/budgets checked afterward. An unavailable or
unverified root control is not supplied by a child selector or a skill invocation.

When a required capability cannot be met in place, report it before dependent work. A human
may explicitly resume a new session through quest-log's sender/receiver contract. Never
start a provider session or mutate config to manufacture switching. Same-session switching
retains ownership; a successor verifies predecessor end and existing recovery authority.
Unknown settings or continuity facts cannot establish a requirement. Record supported,
effective and observed controls separately; private facts remain in existing private notes.

No ADR: #350 already owns shared model policy and #351 already owns session handoffs.
This change supplies the requested application of those placements, without a new interface.

## Success

For forge/campaign coordinators, the three paths remain distinct and preserve effective
overrides, permission restrictions, claim owner, artifact access, full commit identity and
cumulative budgets. Native support is claimed only from the active host contract; bounded
walkthroughs disclose simulated paths and absent live controls.

## Failure model

- Actors/deployments: workflow coordinators in supported local host sessions and explicit successors.
- Invariants/assets: authority, exclusive ownership, commit-bound proof, private artifacts and budgets.
- Accepted failures: absent native controls continue adequate sessions or hold unmet capability;
  inaccessible/stale handoff evidence holds dependent action without automatic reconstruction.
- Covered elsewhere: quest-log claims/handoffs, dispatch-liveness replacement, #258 worker
  assignment, #334 review isolation, #353 escalation, #354/#161 telemetry, existing merge gates.

## Validation

AI-SPEC: workflow operator at a settled phase boundary supplies current host controls, effective
settings and continuity evidence. Output is continue, verified native switch, or explicit
new-session handoff/hold. Sources are active host contracts, actual records and operator
permissions. Invented tools, silent override, duplicate ownership and renewed budgets are
forbidden. Missing requirements follow existing checkpoint/park rules. No new cost/time or
attempt allowance. Success is the observable correct route per bounded case below.
